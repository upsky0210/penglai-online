# P10-A 小規模真人試教準備與課堂彩排

適用規模：1 位老師、5～10 位學生。P10-A 只準備環境與彩排流程；沒有真人參與時，所有結果一律標示為「模擬彩排（非真人試教）」。

## 能力盤點

| 面向 | 現有能力 | P10-A 使用方式 |
|---|---|---|
| 部署 | Windows 一鍵啟動、workspace server/client、health API | 使用前景式 P10-A 啟動器，Ctrl+C 同時停止服務 |
| 教師權限 | 20 字元以上 `ADMIN_TOKEN`、管理 API 權限檢查 | Token 只在啟動程序記憶體中，不寫入 manifest、log 或 CSV |
| 學生帳號 | Google 帳號綁定、帳號存檔槽、訪客存檔 | 真人優先用各自帳號；備援訪客模式必須使用獨立瀏覽器設定檔及指定代號 |
| 資料隔離 | `PENGLAI_DB_PATH`、SQLite 備份／還原 | 每梯使用 `tmp/p10-a/<session-id>/data/penglai.sqlite`，不碰一般資料庫 |
| 課堂觀察 | 教師進度列表、需關注原因、最後活動與死亡次數 | 15 秒以上手動更新，不增加遙測或高頻廣播 |
| 教師介入 | 全班／個別提示、安全區重置、action log | 先提示、後重置；不得替學生完成任務 |
| 課後資料 | 課堂成果、回饋、action log CSV；server console | 匯出到該梯 `exports/`，只用學生代號整理人工觀察 |

## 試教環境與身分隔離

- Session ID 使用日期與梯次，例如 `p10a-20260720-a`，不可含班級、姓名或學號。
- 學生只使用 `S01`～`S10` 代號；人工觀察表不得填真實姓名、email、token 或 session。
- 真人帳號模式：每位學生使用自己的 Google 帳號，且學校需要限制網域時設定 `GOOGLE_HOSTED_DOMAIN`。不同帳號的存檔槽由伺服器綁定。
- 訪客備援模式：每位學生使用不同瀏覽器設定檔／裝置，老師事先分配 `S01`～`S10`；同一瀏覽器設定檔不可多人共用。
- 模擬模式：只可使用虛構的 `example.invalid` 帳號，且必須使用獨立試教 DB；不得把模擬紀錄當成真人成果。
- 教師 `ADMIN_TOKEN` 只由老師輸入，學生端網址不含 token，管理網址不投影 token。

準備模擬梯次：

```powershell
npm.cmd run trial:prepare -- p10a-20260720-a --students 8 --mode simulated
npm.cmd run trial:status -- p10a-20260720-a
```

真人梯次把 `simulated` 改為 `real`。`session.json` 只記錄梯次、模式、人數及資料路徑，不保存任何憑證或學生個資。

## 資料重置

重置前必須停止 server。重置命令要求輸入完整 Session ID；若已有 DB，工具會先建立一致的 `pre-reset-*.sqlite` 備份，才移除該梯的 active DB、WAL 與 SHM：

```powershell
npm.cmd run trial:reset -- p10a-20260720-a --confirm-reset=p10a-20260720-a
npm.cmd run trial:status -- p10a-20260720-a
```

此動作只允許作用於 P10-A session 子目錄，不會清除一般 `server/data/penglai.sqlite`。若要保留一次完整彩排證據，改用新的 Session ID，不要重置舊梯次。

## 啟動與停止

Windows 啟動器會先準備 session、檢查固定埠、以遮罩提示讀取教師 Token，再以前景方式啟動 client 與 server：

```powershell
npm.cmd run trial:start -- -SessionId p10a-20260720-a -Students 8 -Mode simulated
```

真人試教使用 `-Mode real`。啟動後：

- 學生入口：`http://老師電腦IP:5174`
- 教師入口：`http://老師電腦IP:5174/?admin=1`
- 停止：回到啟動終端按一次 Ctrl+C，等待 client/server 都顯示結束，再關閉終端。
- 停止後清除投影畫面的教師頁，並執行 `trial:status` 確認 DB integrity 為 `ok`。

## 緊急回復

1. 宣告全班暫停操作，記錄時間與學生代號，不要求學生重複送出。
2. 在啟動終端按 Ctrl+C；不要直接刪 DB，也不要在 server 運作時還原。
3. 若只是單一學生卡地形，重新啟動後優先使用「送回安全區」，不得重置全梯資料。
4. 若資料庫異常，先複製 server console 最後 30 行到問題紀錄，再用本梯最新備份還原：

```powershell
$env:PENGLAI_DB_PATH = "tmp/p10-a/p10a-20260720-a/data/penglai.sqlite"
npm.cmd run restore:db -- "tmp/p10-a/p10a-20260720-a/backups/備份檔.sqlite" --confirm
npm.cmd run trial:status -- p10a-20260720-a
```

5. 只有 integrity 為 `ok` 才重新啟動。無法在 5 分鐘內安全恢復時結束遊戲活動，改做口頭歷史回顧；不得臨時清除學生進度。

## 30～45 分鐘課堂執行表

| 時間 | 老師／觀察者 | 學生 | 必記事件 |
|---|---|---|---|
| 0–5 分 | 確認 5～10 人上線、說明代號與真實歷史／奇幻設定區別 | 登入或建立訪客角色，完成 A/D/W/E | 登入成功時間、首位 NPC、無法進入者 |
| 5–12 分 | 不先口頭教答案；必要時發全班方向提示 | 完成首次戰鬥、拾取與第一個任務回報 | 首任務完成時間、操作誤解、教師提示時間 |
| 12–20 分 | 查看目前任務、最後活動與需關注標記 | 往下一目標移動，至少一次使用 H | 卡關原因、H 提示是否有用、死亡及復活 |
| 20–28 分 | 只對需要者發個別提示；地形問題才安全重置 | 閱讀短對話／互動史實並前往滬尾 | 個別提示、安全重置、重連、存檔 |
| 28–35 分 | 問「這裡靠什麼產業發展？」 | 用一句話回答產業 | 是否引用遊戲內線索、混淆奇幻／史實處 |
| 35–40 分 | 問「這個地方如何與外界連結？」並請按 T 回饋 | 回答連外方式、送出回饋 | 歷史內容反應、回饋是否成功 |
| 40–45 分 | 匯出課堂成果、action log、回饋 CSV；建立備份 | 分享觀察、正常離線 | CSV 人數、存檔／重連結果、結束時間 |

30 分鐘版本在第 28 分鐘直接進入兩題歷史回顧；45 分鐘版本保留重連／安全重置示範與分享。
