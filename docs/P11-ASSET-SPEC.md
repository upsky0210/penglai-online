# P11 素材規格表

> 2026-11-13。造型與色彩規則見 [P11-ART-BIBLE-V2.md](P11-ART-BIBLE-V2.md);工作順序見 [P11-ART-UPGRADE-PLAN.md](P11-ART-UPGRADE-PLAN.md)。
> 本文件是量產的硬規格。要改尺寸或幀數,先改這份文件再動手。

## 1. 共通規則

### 1.1 目錄

所有新素材放 `client/public/assets/p11/`。舊的 `p8/`、`p9/` 不動,當缺圖時的回退。

```text
client/public/assets/p11/
  items/            物品介面圖示(96×96)
  item_drops/       物品掉落圖(40×40)
  skills/           招式特效 sprite sheet
  skill_icons/      技能列圖示(96×96)
  characters/       talisman/、hunter/ 的職業動作
  npcs/portraits/   半身立繪(256×320)
  npcs/sprites/     NPC 手勢動作與單機版 NPC 待機
  ui/               題字圖
```

### 1.2 檔名

英文小寫、底線、不含空白與中文。物品與 NPC 的檔名直接用遊戲資料的 id,把連字號換成底線:`small-hp-potion` → `small_hp_potion.png`。

### 1.3 兩種顯示路徑(重要)

遊戲畫布固定是 960×540,瀏覽器再把整張畫布放大到螢幕。**畫進畫布的圖,再高解析也會先被縮到 960×540**,多出來的像素等於丟掉。所以:

| 素材 | 顯示方式 | 匯出解析度 |
| --- | --- | --- |
| 角色、NPC 小人、怪物、招式特效、掉落物 | 畫布(Phaser) | 1 倍,照下面各節的格子尺寸 |
| 物品圖示、立繪、技能圖示、題字 | **DOM 疊層**(HTML/CSS 疊在畫布上) | 2 倍,全螢幕下才會清楚 |

這表示背包、對話框、取得提示、技能列這四個新介面要做成 DOM 疊層,而不是沿用現在的 Phaser 文字面板。專案已有 DOM 介面的先例(`client/src/ui/FeedbackForm.ts`)。介面規格見 §7。

「畫布固定 960×540」是讀 `main.ts` 的設定推得的。P11-2 開工時先在瀏覽器確認 `canvas.width === 960`;若不是,回報後再調整本節。

### 1.4 生成與處理

- 原圖以純色色鍵背景生成(主體偏綠用洋紅 `#ff00ff`,其他用綠 `#00ff00`),去背後再裁切縮放。
- 原圖放 `tmp/imagegen/p11/`(被 git 忽略)。每完成一包,把該包原圖壓縮備份到 repo 外,並把備份位置寫進交付文件。
- **同一張 sprite sheet 的所有幀必須用同一個縮放比例。**現有 `scripts/build-p8-sprites.py` 的 `fit_subject` 是每一幀各自縮放到最大尺寸,會讓角色或特效在幀與幀之間忽大忽小。新的建置腳本要先算整列的共同比例,再套到每一幀。
- 角色與 NPC:腳底線固定,每幀腳底的 y 相同。特效:中心點固定。
- 提示詞不寫任何作品名、角色名(Bible §2)。
- 圖上不得有文字。需要文字的素材(題字)用字型產生,不用圖像生成。

### 1.5 素材紀錄

每張成品在 `scripts/assets/p11-records.json` 留一筆(這個檔要進版控):

```json
{
  "file": "client/public/assets/p11/items/coral_key.png",
  "kind": "item-icon",
  "gameId": "coral-key",
  "prompt": "(完整提示詞)",
  "referenceImages": ["docs/art/p8_anping_style_anchor.png"],
  "keyColor": "#00ff00",
  "sourceFile": "tmp/imagegen/p11/items/coral_key_src.png",
  "sourceSha256": "(雜湊)",
  "frame": { "width": 96, "height": 96, "count": 1 },
  "generatedAt": "2026-11-20",
  "notes": ""
}
```

## 2. 完整性檢查 `check:assets`

P11-1 要寫的腳本。以下任一不成立就以非零碼結束:

1. `ITEM_DEFINITIONS` 每個 id 在 `p11/items/` 與 `p11/item_drops/` 各有一張圖。P11-3 完成前允許用白名單暫時豁免,白名單清空才算完成。
2. 每個 `CLASS_SKILL_IDS` 的技能有 §4 列的全部特效與一張技能圖示。
3. 每個地圖 NPC id 有立繪;`AnpingScene` 的三名 NPC 有立繪與待機圖。
4. 每張 sprite sheet 的寬度等於「格寬 × 幀數」,高度等於格高。
5. 每一幀四個角落透明;每一幀左右邊界兩像素內沒有不透明像素(防止相鄰幀滲入)。
6. 同一張 sheet 各幀的主體高度差不超過 12%(角色與 NPC 待機、跑步適用;攻擊與特效不檢查)。
7. `p11-records.json` 裡每一筆的檔案存在,且每張 `p11/` 下的圖都有紀錄。

## 3. 物品(28 件)

- 介面圖示:`p11/items/<id>.png`,96×96,主體落在中央 84×84 內。DOM 顯示。
- 掉落圖:`p11/item_drops/<id>.png`,40×40,主體落在 36×36 內、貼底。畫布顯示。由介面圖示縮小產生,縮小後看不清的要手動簡化重畫。
- 原圖至少 512×512。
- 品階與說明文要加進 `ItemDefinition`(新欄位 `rarity`、`description`)。**id、name、數值都不動**,所以不需要存檔遷移。
- 章節欄是依名稱與數值推定的,動工時要對照伺服器掉落表與商店確認。

圖示要同時說得通「現在的名字」與「所在的歷史章節」。例如珊瑚潮鑰出現在大稻埕茶市,就畫成茶箱的銅鎖鑰,鑰柄帶珊瑚枝紋。

## 4. 招式

全部在畫布顯示,1 倍匯出。放 `p11/skills/`。播放速率見表;混合模式的「加亮」指 Phaser 的 ADD。

### 4.1 技能特效(每個技能四張)

| 段 | 檔名 | 格 | 幀數 | fps | 混合 | 何時播 |
| --- | --- | --- | --- | --- | --- | --- |

| --- | --- | --- | --- | --- |
| `sword-cleave` | 192×128 | 墨色刀痕 → 浪峰升起 → 浪尖回捲 → 碎成水珠 | 腳邊一圈潮紋 | 落下的水珠與淡淡水氣 |

預設都是「不改」。使用者沒有明確同意前,Codex 不得自行改名。

1. **技能名。**題字會把名字放大。現名「斬擊、靈符、狙擊」符合 D8 的命名規則,但偏平淡。D8 允許「自然物 + 動詞」格式,可改成破浪斬、鎮霧符、引星射一類。改名只動顯示名,不動 id。
