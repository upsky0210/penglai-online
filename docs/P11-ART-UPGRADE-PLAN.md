## 3. 美術方向:參考什麼、不能拿什麼

軒轅劍參/天之痕是 2D 水墨手繪,之後轉 3D;仙劍三起也是 3D。本作是 2D 橫向捲軸,能借的是**演出語法**,不是造型:

| 可以借的做法 | 落到本作的樣子 |
| --- | --- |
| 招式多段演出、招式名題字 | 起手光 → 本體 → 命中 → 餘韻;放招時角色頭上浮出毛筆題字的招式名 |
| 屬性有固定的色彩語彙 | 三種「異相」:**潮**(青藍)、**霧**(灰白)、**星**(紫銀),對應既有設計決策 D7 的三種自然律紊亂,也對應劍士、符咒師、獵人。另有兩個人間色**墨**(黑金)與**燈**(暖橘)當輔色。只當視覺語言,不加傷害相剋,所以不動平衡。初稿寫的是五相並列,對照 D7 後改成三相加二色 |
| 對話時的半身立繪與名牌 | 每名 NPC 一張半身立繪,服裝維持 1860–1955 臺灣史實考據 |
| 寶物有精緻單品圖、品階、取得演出、說明文 | 四階品級色框(尋常/上選/珍藏/異聞);取得時彈出圖示與名稱;說明文可以帶一句地方史料 |

**不能拿的:**兩個系列的角色名、招式名、法寶名、屬性體系名稱、角色臉型髮型服裝、UI 版面、音樂。生圖提示詞裡也不寫作品名稱,只寫具體的視覺描述。

**Bible v2 原則(已定案):**「人物是史實的,異聞是華麗的。」NPC、服裝、器物維持歷史考據;招式與寶物屬於異聞層,允許大範圍光效與題字,但限制在三相二色的色盤內,且本體遮住角色不超過 0.5 秒。完整規則見 P11-ART-BIBLE-V2。

## 5. 模型分工

### 5.1 兩個事實先講

1. **Claude Code 不能生點陣圖**,只能看圖、寫程式、寫規格。這次美化的主體是生圖,P8 當時用的也是 Codex 內建的圖像生成,所以素材製作只能在 Codex 那邊。
2. Claude 用量要留給別的專案,所以 Claude 只做「判斷密度高、輸出量小」的事:定規範、審風格、審伺服器改動、最終把關。

### 5.2 採用方案 A:Codex 主做,Claude 把關

使用者指定 Codex 主要用 `sol-6.1`(約同 Opus 5.5)與 `astra-6`(約同 Fable 5.1)。

| 工作包 | 執行者 | 模型層級 | 理由 |
| --- | --- | --- | --- |
| P11-0 規範(已完成) | Claude Code | 本 session | 侵權邊界與風格取捨是判斷題,後面所有工作都照這份做,錯了最貴 |
| P11-1 管線工具 | Codex | `sol-6.1` | 規格明確、有機器驗收 |
| P11-2 垂直切片 | Codex | `astra-6` + 圖像生成 | 風格一致性與第一次整合最吃能力 |
| 切片審查 | 你本人 + Claude Code | Sonnet 5.5,短 session | 換一雙眼睛看截圖與 diff;風格過不過由你決定 |
| P11-3 物品量產 | Codex | `sol-6.1` + 圖像生成 | 重複性高,照切片規格跑 |
| P11-4 招式量產 | Codex | `astra-6` + 圖像生成 | 動畫對齊與特效時間軸較難 |
| P11-5 NPC 量產 | Codex | `sol-6.1` + 圖像生成 | 同 P11-3 |
| P11-6 單機版整合 | Codex | `astra-6` | 單檔重構,有瀏覽器流程可驗 |
| P11-7 總驗收 | Claude Code | Opus 5.5,一個短 session | 侵權對照與 `check:release` 結果的獨立把關 |

Claude 總共三個短 session:P11-0(已完成)、切片審查、總驗收。Fable 5.2 不需要常態使用,只有遇到跨多個系統又卡住的問題才值得開。Haiku 5.5 不適合這幾項。

### 5.3 其他方案

- **方案 B:全部交給 Codex。**Claude 用量為零。代價是沒有獨立審查,同一個模型自己寫、自己驗。要走這條,建議把 `check:assets`、禁用詞檢查做扎實,並由你本人看每一包的截圖。
- **方案 C:Claude 寫程式,Codex 只生圖。**程式整合品質最穩,但 P11-1、4、6 都是大量輸出,Claude 用量最高,與你現在的用量分配不合,不建議。

### 5.4 Codex 模型名稱

使用者於 2026-11-13 提供:`sol-6.1` 與 `astra-6`。初稿查到的 7 月公開清單已過期,不再採用。

### 5.5 交接規則

- 每包開工前,執行者先讀 `CLAUDE.md`、本文件、Art Bible v2 與最新一份 DAY/交接文件。
- 一包一個 commit;commit 完才換下一個工具。
- 改到 `server/` 或 `shared/` 一定重啟 dev server 再跑 smoke。
- 素材只放 `client/public/assets/p11/`,舊的 `p8/`、`p9/` 先保留當回退,P11-7 再決定是否移除。

## 7. 風險

- **生圖風格飄移**:量產前一定要有切片與風格錨點;每批素材進 gallery 與舊圖並排比對。
- **動畫幀不對齊**:角色腳底線、特效中心點由建置腳本強制檢查,不靠肉眼。
- **特效太多拖垮低階機**:沿用 P8-G4 的同屏上限與低階模式,新特效的次要層在低階模式關閉。
- **參考作品太像**:提示詞不寫作品名;P11-0 定禁用詞;P11-7 人工對照。
- **兩個工具互相覆蓋**:嚴格串行或各開 worktree(2026-07-05 出過事)。
